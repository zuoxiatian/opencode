# 结算原始输入文件检查

使用本技能判断一个 Excel 是否可以作为**结算原始输入文件**继续进入 Excel 转 PPT 流程。它的目标不是制作 PPT，而是在制作前先确认：第一个工作表是否能作为汇总表，汇总表第一列的板块信息是否能与后续分表一一对应，所有数据区文本字段是否完整。图片在当前业务口径下不作为 sheet 级必要条件：每个工作表可以有图也可以无图；但如果某个工作表中真实检测到某一列已经插入图片，则该列会被识别为**实际有图列**，并对该列所有有效数据行逐行检查是否存在真实嵌入图片，文本占位不能替代图片。

## 什么时候使用

当用户上传一个或多个结算相关 Excel，并询问“这个表是否符合标准”“能不能转 PPT”“为什么这个文件不能用”“这是原始输入文件还是交付结算文件”“图片识别到了哪些列”“哪一行文本内容没填全”时，先使用本技能做结构与内容校验。

如果检查结果是**符合标准**，再继续使用 `/excel-to-pptx` 生成 PPT。如果检查结果是**不符合标准**，先向用户说明缺少什么、哪一行或哪一列不完整、哪张分表不能对应汇总表，以及建议如何补齐。

## 核心判断口径

标准样本是 `结算原始输入文件-测试002.xlsx`。这个文件的特点是：第一个 sheet 是汇总表，后续 sheet 是按业务类型拆分的分表；汇总表第一列记录板块信息，分表名称应能与这些板块值匹配；数据区域除备注、说明、补充、其他、可选等可空列外，文本字段应保持逐行逐字段完整；图片类字段不纳入文本占位检查，但只要在某个字段列中真实检测到嵌入图片，该列就需要按有效数据行逐行检查真实图片是否完整。

| 检查内容 | 合格文件应具备的表现 |
| --- | --- |
| 汇总表位置 | 第一个 sheet 默认视为汇总表，不依赖 sheet 是否一定命名为 `汇总`。 |
| 板块列位置 | 汇总表第一列默认视为板块列，不依赖列名是否一定叫 `板块`。 |
| 汇总与分表对应 | 汇总表第一列的每个板块值应能与后续分表 sheet 名匹配；汇总表有板块但无分表、或分表无对应板块，都必须报错。 |
| 数据区完整性 | 任意 sheet 的数据区中，除备注、说明、补充、其他、可选等可空列外，文本字段都应逐行有值；图片类字段不使用文本内容判定是否完整。 |
| 图片列识别 | 系统会根据工作表中真实嵌入图片的锚点位置，识别图片所在字段列，并统计图片数量、图片所在列和每行最多图片数，供后续流程参考；若常规读取接口未返回图片，会继续解析 XLSX 内部 drawing XML 作为兜底，避免图片被误判为 0。 |
| 图片非 sheet 必需 | 每个 sheet 可以有图片，也可以没有图片；不会因为某个 sheet 无图而阻断，也不会因为表头写了 `截图`、`凭证` 或 `必填` 但整列无真实图片而凭空触发缺图。 |
| 实际有图列逐行检查 | 只要某个字段列真实检测到至少一张嵌入图片，该字段就被视为实际有图列；系统会检查该列所有有效数据行是否都有真实图片，并返回所有缺图原始行号。仅填写“已截图”等文字不算通过。 |
| 全量返回问题 | 每个 sheet 的所有问题都应累计返回，不应检测到第一个问题后停止。 |
| 合法非数据行 | 分表中的合法汇总公式尾行、合计行、小计行、总计行、说明行和备注行可以不算入数据区完整性检查。 |

## 字段匹配与边界规则

字段匹配不是完全等值匹配，而是先做归一化，再按同义词进行精确、包含、被包含匹配。例如，`媒体名称（必填）` 可以匹配 `媒体名称`，`平台` 可以匹配 `发布平台`，`达人`、`达人名称`、`账号名称` 可以匹配 `媒体名称`。

| 边界 | 当前处理方式 |
| --- | --- |
| 备注/说明类列可以为空 | 表头包含 `备注`、`说明`、`补充`、`其他`、`可选` 的列默认视为可空列，不强制逐行检查。 |
| 汇总表与板块列不依赖名称 | 第一个 sheet 默认是汇总表，第一列默认是板块列；即使 sheet 或列名不同，也按该位置规则检查。 |
| 合法尾行不算数据行 | 只包含汇总公式的尾行，以及只有 `合计`、`小计`、`总计`、`说明`、`备注` 等短标签的行，不作为明细数据行检查。 |
| 图片列的两层规则 | 表头包含 `截图`、`图片`、`凭证`、`合同`、`发票`、`付款` 等图片类关键词时，默认不纳入文本必填完整性检查；但图片逐行检查不依赖这些关键词或 `必填` 标记，而是由该列是否真实检测到嵌入图片触发。 |

## 怎么运行检查

运行下面的命令检查一个 Excel 文件：

```bash
python /home/ubuntu/skills/settlement-excel-validator/scripts/validate_settlement_excel.py <input.xlsx> --out-dir <output_dir>
```

检查后会生成两份结果文件：

| 文件 | 给谁看 | 说明 |
| --- | --- | --- |
| `validation_report.md` | 给业务用户看 | 用中文说明该 Excel 是否合格、各工作表概况、发现的问题和修改建议。 |
| `validation_result.json` | 给后续自动化流程使用 | 保留机器可读取的检查结果，不需要主动展示给非技术用户。 |

默认按标准样本做严格检查。如果用户明确表示“只想大概看看结构是否可用”，可以使用宽松检查：

```bash
python /home/ubuntu/skills/settlement-excel-validator/scripts/validate_settlement_excel.py <input.xlsx> --mode relaxed --out-dir <output_dir>
```

## 给用户反馈时怎么说

反馈时优先使用业务语言，不要把脚本、字段编号、程序判断逻辑作为重点。推荐按下面的方式说明：

| 场景 | 推荐表达 |
| --- | --- |
| 文件合格 | “这个 Excel 符合结算原始输入文件标准，可以继续用于生成 PPT。” |
| 分表无法对应汇总表 | “这个分表在汇总表第一列里找不到对应板块，后续无法判断它应使用哪条结算信息。” |
| 汇总表板块无对应分表 | “汇总表第一列有一条板块信息，但没有找到名称可匹配的分表，请确认是否漏建或改名。” |
| 图片识别结果 | “这个工作表中识别到了图片，报告会列出图片数量和所在列；图片不是 sheet 级必填项，但凡是实际插入过图片的字段列，都会检查每条有效数据是否也插入了真实图片。” |
| 文本字段缺失 | “这个字段属于数据区必检字段，但部分数据行为空，报告中列出了具体 Excel 原始行号。” |
| 有风险但不阻止 | “这个问题不一定会导致失败，但可能影响后续 PPT 展示效果，建议确认。” |

## 问题严重程度

检查结果分为两类。向用户说明时，应把“必须修正的问题”放在前面，把“建议确认的问题”放在后面。

| 类型 | 含义 | 处理建议 |
| --- | --- | --- |
| 必须修正 | 不修正就不建议继续转 PPT。 | 请用户补齐汇总表板块、对应分表、缺失文本内容，或实际有图列中缺失的图片后再处理。 |
| 建议确认 | 文件可能仍能继续使用，但存在格式或内容风险。 | 告知用户风险，让用户决定是否继续。 |

## 本次兼容性修复

当前版本在常规图片读取之外，增加了对 `.xlsx` 内部 `xl/drawings/*.xml` 与关系文件的兜底解析。这个修复用于处理某些环境、只读读取模式或依赖差异导致 `ws._images` 为空、从而把真实嵌入图片统计为 0 的情况。

## 规则文件

具体检查规则保存在：

```text
/home/ubuntu/skills/settlement-excel-validator/references/standard_schema.json
```

如果业务标准发生变化，例如新增分表、改变哪些文本列应视为可空列、调整实际有图列的触发阈值，或改变合计/说明行的识别关键词，应更新规则文件。`SKILL.md` 只保留使用方法和面向用户的解释口径。
