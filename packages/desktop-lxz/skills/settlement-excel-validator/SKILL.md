# 结算原始输入文件检查

使用本技能判断一个 Excel 是否可以作为**结算原始输入文件**继续进入 Excel 转 PPT 流程。它的目标不是制作 PPT，而是在制作前先帮用户确认：这个文件是不是正确的原始输入表，是否包含汇总页、各类明细页、必填字段，以及汇总页和明细页是否能够对应起来。

## 什么时候使用

当用户上传一个或多个结算相关 Excel，并询问“这个表是否符合标准”“能不能转 PPT”“为什么这个文件不能用”“这是原始输入文件还是交付结算文件”时，使用本技能先做检查。

如果检查结果是**符合标准**，再继续使用 `/excel-to-pptx` 生成 PPT。如果检查结果是**不符合标准**，先向用户说明缺少什么、哪里不像标准原始输入表，以及建议如何补齐。

## 判断口径

标准样本是 `结算原始输入文件-测试002.xlsx`。这个文件的特点是：先有一个 `汇总` 工作表，再有若干个按业务类型拆分的明细工作表；汇总表里有明确的必填字段，每个明细表都能对应到汇总表中的一行。

对比样本 `317交付文件-测试0513.xlsx` 不属于合格的原始输入文件。它更像已经整理好的交付或结算展示文件，缺少 `汇总` 工作表，也没有标准的明细工作表名称和必填字段。

| 检查内容 | 合格文件应具备的表现 |
| --- | --- |
| 是否有汇总页 | 文件中应有名为 `汇总` 的工作表，用来说明每类明细对应的结算信息。 |
| 是否有标准明细页 | 应包含 `1-车马费合作-云评`、`2-车马费合作-通稿`、`3-媒体合作-线下合同`、`4-媒体合作-平台单链接`、`5-媒体合作-平台多链接`、`6-差旅` 等明细页。 |
| 汇总页字段是否完整 | 汇总页应包含板块、描述方向、媒体名称、单价、数量、单位、总价、RFQ、备注等必填信息。 |
| 明细页是否能对应汇总页 | 每个明细页都应能找到对应的汇总记录，方便后续 PPT 每页展示正确的结算说明。 |
| 表格是否像原始输入表 | 合格文件应是可继续处理的结构化表格，而不是已经排版好的结算单、交付清单或展示型表格。 |
| 图片和凭证是否保留 | 如果明细页包含截图、发票、付款凭证、合同等图片，应能在检查结果中识别出来，便于后续排版。 |

## 怎么运行检查

运行下面的命令检查一个 Excel 文件：

```bash
python /home/ubuntu/skills/settlement-excel-validator/scripts/validate_settlement_excel.py <input.xlsx> --out-dir <output_dir>
```

检查后会生成两份结果文件：

| 文件 | 给谁看 | 说明 |
| --- | --- | --- |
| `validation_report.md` | 给业务用户看 | 用中文说明该 Excel 是否合格、各工作表概况、发现的问题和修改建议。 |
| `validation_result.json` | 给后续自动化流程使用 | 保留机器可读取的检查结果，不需要主动展示给非技术用户。 |

默认按标准样本做严格检查。如果用户明确表示“只想大概看看结构是否可用”，可以使用宽松检查：

```bash
python /home/ubuntu/skills/settlement-excel-validator/scripts/validate_settlement_excel.py <input.xlsx> --mode relaxed --out-dir <output_dir>
```

## 给用户反馈时怎么说

反馈时优先使用业务语言，不要把脚本、字段编号、程序判断逻辑作为重点。推荐按下面的方式说明：

| 场景 | 推荐表达 |
| --- | --- |
| 文件合格 | “这个 Excel 符合结算原始输入文件标准，可以继续用于生成 PPT。” |
| 缺少汇总页 | “这个文件缺少 `汇总` 工作表，后续无法判断每个明细页对应哪一条结算信息。” |
| 缺少标准明细页 | “这个文件的工作表名称和标准原始输入文件不一致，建议先按标准模板补齐明细页。” |
| 像交付结算单 | “这个文件更像已经排版好的结算单或交付文件，不是用于生成 PPT 的原始输入表。” |
| 有风险但不阻止 | “这个问题不一定会导致失败，但可能影响后续 PPT 展示效果，建议确认。” |

## 问题严重程度

检查结果分为两类。向用户说明时，应把“必须修正的问题”放在前面，把“建议确认的问题”放在后面。

| 类型 | 含义 | 处理建议 |
| --- | --- | --- |
| 必须修正 | 不修正就不建议继续转 PPT。 | 请用户补齐汇总页、标准明细页或关键字段后再处理。 |
| 建议确认 | 文件可能仍能继续使用，但存在格式或内容风险。 | 告知用户风险，让用户决定是否继续。 |
